## ⚠️ `name` → `title` is a deliberate deviation

The tracker is explicit that the canonical doc calls this `name` and that
renaming to `title` is an *intentional extension*. The same rename is applied to
`UserType` (see [05](05-users.md)) — and **only** to those two models. `Collection`,
`Postcard`, `Subcollection`, `CollectionCluster`, `Tag`, `FacetType`,
`FacetValue`, `Media`, and all four geo tiers keep `name`.

That inconsistency is what the tracker specifies. Worth one confirmation before
implementing, since a half-applied rename is worse than either convention.

tracker says does not exist in the real schema.

Either the pasted schema was partial, or that code path is dead. Covered as
**decision D5** in [06](06-directory-album.md).

## Target model

```
model Company {
  id                 BigInt        @id @default(autoincrement())
  title              String        @map("title")             // RENAMED from name
  slug               String        @unique
  contactEmail       String?       @map("contact_email")
  contactPhone       String?       @map("contact_phone")
  website            String?
  logoMediaId        BigInt?       @map("logo_media_id")     // RENAMED from icon_media_id
  coverImageMediaId  BigInt?       @map("cover_image_media_id")  // NEW
  status             CompanyStatus @default(pending)
  logo       Media? @relation("CompanyLogo",       fields: [logoMediaId],       references: [id])
  coverImage Media? @relation("CompanyCoverImage", fields: [coverImageMediaId], references: [id])
  ...
}
```

The `Media` back-relation `companyIcons` renames to `companyLogos`, and a new
`companyCoverImages` is added (see [03](03-media.md)).

## Script impact

`company.py` needs:

1. `INSERT INTO companies (name, ...)` → `(title, ...)`, and the same in the
   `ON CONFLICT DO UPDATE` set.
2. Fetch `{"populate": "icon"}` → `{"populate": "logo,coverImage"}`.
   ⚠️ The script currently reads `a.get("icon")` but the tracker names the v1
   field **`logo`**. Confirm which the live CMS exposes — if the endpoint really
   returns `icon`, only the *target* column renames.
3. Add the `coverImage` → `cover_image_media_id` resolution, reusing the same
   find-or-create-by-url path.

### Knock-on: `users.py` matches companies by name

`users.py` line 272 builds `company_by_name` from `SELECT TRIM(name), id FROM
companies`, and `directory_album.py` line 199 does
`SELECT LOWER(name), id FROM companies`. Both break on the rename and must
become `title`.

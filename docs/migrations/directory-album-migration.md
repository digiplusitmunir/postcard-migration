# Directory & Album Migration

Everything about migrating legacy Strapi `directories` into `collection_types`
and `albums` into `collections` (tracker rows **#6** and **#14** — Collection
half only). Executed by `scripts/directory_album.py` (step 6 of
`scripts/migrate_data.py`); the same logic lives in
`notebooks/directory_album_migration.ipynb` for interactive runs, which also
carries the optional author/assigned_staff circles step (notebook only).

## Scope decisions (2026-08-06)

- **Designer Tours is skipped entirely** — the directory and its 59 albums
  become dx-card / Destination Expert data later (tracker rows #11/#13).
- **Journey subcollections are NOT created here** (deferred). The dual-price
  fix (`subcollections.price_starting_at`, schema migration
  `20260806060000_add_subcollection_price_starting_at`) is already in place
  for when that step runs.
- **Circles are NOT created by the script** — legacy `album.user` → Circle
  `author` and `album.assignTo` → Circle `assigned_staff` exist only as the
  optional section 6 of the notebook, for when circle work unblocks.

## Field mapping — Directory

Legacy `api::directory.directory` → new `collection_types`. The v1 directory
list is **reconciled to the fixed v2 set** — fixed v2 names/slugs win:

| Legacy directory (slug) | New collection type | `has_dedicated_collection` | `priority` |
|---|---|---|---|
| Postcard StarPartner Stays (`mindful-luxury-hotels`) | Properties (`properties`) | true | 1 |
| Food and Beverages (`food-and-beverages`) | Restaurants (`restaurants`) | false | 2 |
| Postcard Events (`postcard-events`) | Events (`events`) | false | 3 |
| Postcard Shopping (`postcard-shopping`) | Shopping (`shopping`) | false | 4 |
| Designer Tours (`mindful-luxury-tours`) | **skipped** — dx-card migration later | | |

| Legacy field | New column | Notes |
|---|---|---|
| `description` | `description` | trimmed; empty → NULL |
| `logo` (media) | `icon` | the logo **url string** (absolutized against `CMS_BASE_URL`) — `collection_types.icon` is a string column, not a media FK |
| `name`, `slug` | — | replaced by the fixed v2 names/slugs above |
| `label`, `seo`, timestamps | — | **dropped** |

Any directory that is neither mapped nor skipped is printed under
`MANUAL REVIEW (unmapped)` — expected empty.

## Field mapping — Album

Legacy `api::album.album` → new `collections`.

| Legacy field | Type | New column | Notes |
|---|---|---|---|
| `name` | string | `name` | trimmed; albums without a name are skipped → printed list |
| `slug` | string | `slug` (unique) | ~665 legacy albums have an empty slug → generated by slugify(name); all slugs de-duplicated in-run (`foo`, `foo-2`, ...) — processing is id-sorted so suffixes stay stable across re-runs |
| `directories` | manyToMany | `collection_type_id` (FK) | first directory wins; Designer Tours albums are skipped; albums with **no** directory default to Properties → printed list |
| `intro` / `story` | text | `intro` / `story` | trimmed; empty → NULL |
| `coverImage` | media | `cover_media_id` (FK → `media`) | find-or-create by normalized url (same normalization as `scripts/media.py`, so existing rows are reused, never duplicated) |
| `seo` | component | `seo` (jsonb) | empty values and the component `id` stripped |
| `isFeatured` | boolean | `is_featured` | |
| `priority` | int | `priority` | NULL → 0 |
| `country` | relation | `country_id` (FK) | matched **by name** (that's how geo migrated); misses printed for review |
| `region` | relation | `region_id` (FK) | matched by (name, country); misses printed for review |
| `locality` | relation | `locality_id` (FK) | matched by name only when the name is unique; ambiguous names printed for review |
| `company` / `companySlug` | relation / string | `managed_by_company_id` (FK) | relation matched by name, else the `companySlug` string by slug (raw, then slugified); misses printed for review |

## Output artifact — legacy album id map

The script writes `legacy_album_id_map_dev.json` / `_prod.json` (legacy
album id → new collection id) to the repo root — the postcards migration
needs it. The suffix is picked automatically from the DB name in
`DATABASE_URL` (`development` → `_dev`, `production` → `_prod`).

## Idempotency

`collection_types` and `collections` both upsert on `slug`
(`ON CONFLICT (slug) DO UPDATE`). Cover-image media rows are found-or-created
by url. Generated slug suffixes are stable because processing is id-sorted.
Safe to re-run.

## What needs manual work — checklist

1. **Unmapped directories** — `MANUAL REVIEW (unmapped)` should be empty; any
   entry means a new legacy directory appeared and needs a mapping decision.
2. **No-directory albums** (~35) — they default to Properties; review the
   printed list and reassign collection types where wrong.
3. **Geo misses** — regions not found (~15: Santa Cruz, Luang Prabang, Dubai,
   ...) and ambiguous localities (~12: Shanti Nagar ×2) leave the FK NULL;
   fix by hand after deciding the right target rows.
4. **Unmatched companies** (~6) — albums whose company relation/slug found no
   `companies` row keep `managed_by_company_id` NULL.
5. **Slug review** — generated/de-duplicated `-2` suffixes are
   customer-facing; review anything that looks off.
6. **Circles** — run notebook section 6 when circle work unblocks (needs
   `USER_MAP_FILE` in `.env` pointing at the right per-environment user map).
7. **Deferred work** — Journey subcollections, facets
   (`album_themes`/`category`/`environment`/`cuisines`), postcards and
   memories all have their own tracker rows.

## Verification

The script ends with per-type counts and totals. Expected (prod, 2026-08-06):
~2,767 collections — Properties ~2,108 (2,073 + 35 no-directory defaults),
Restaurants 341, Shopping 235, Events 84; ~2,300 with cover; ~2,700 with
country; 1,684+ live; 0 duplicate slugs; 59 Designer Tours albums skipped.

## Run order

```text
seed → geo → media → company → users → scripts/directory_album.py
```

Must run **after** geo (country/region/locality lookups), media (cover
reuse), company (managed_by links) and seed (base collection types), and
**before** the postcards/memories migrations (they need
`legacy_album_id_map.json`). Or just run `python scripts/migrate_data.py`,
which sequences everything and stops on the first failure.

# Directory & Album Migration

Everything about migrating legacy Strapi `directories` into `collection_types`
and `albums` into **`collections` or `postcards`** (tracker rows **#6** and
**#14**). Executed by `scripts/directory_album.py` (step 6 of
`scripts/migrate_data.py`); the same logic lives in
`notebooks/directory_album_migration.ipynb` for interactive runs, which also
carries the optional author/assigned_staff circles step (notebook only).

## The album split — collections vs postcards

Only collection types with a real Collection layer
(`has_dedicated_collection = true`, i.e. **Properties**) get `collections`
rows. **Restaurants, Events and Shopping** have
`has_dedicated_collection = false` — there is no Collection layer for them,
so their albums *are* the content and migrate straight into **`postcards`**:

| Album's collection type | `has_dedicated_collection` | Album becomes | `collection_id` | prod albums |
|---|---|---|---|---|
| Properties | `true` | a `collections` row | — | 2,072 (+35 no-directory) |
| Restaurants | `false` | a `postcards` row | **NULL** | 341 |
| Shopping | `false` | a `postcards` row | **NULL** | 235 |
| Events | `false` | a `postcards` row | **NULL** | 91 |
| Designer Tours | — | **skipped** (dx-card migration) | — | 59 |

Those 667 postcards keep `collection_type_id` pointing at Restaurants /
Events / Shopping and carry geo (`country_id`/`region_id`/`locality_id`)
directly — exactly the shape `schema.prisma` documents for the
non-dedicated types.

The split is driven by the `has_dedicated_collection` flag **read back from
the DB** after the directory step, not by a hard-coded slug list, so
flipping the flag for a type is all it takes to change which side an album
lands on.

## Scope decisions (2026-08-06, album split added 2026-08-11)

- **Designer Tours is skipped entirely** — the directory and its 59 albums
  become dx-card / Destination Expert data later (tracker rows #11/#13).
- **Journey subcollections are NOT created here** (deferred). The dual-price
  fix (`subcollections.price_starting_at`, schema migration
  `20260806060000_add_subcollection_price_starting_at`) is already in place
  for when that step runs.
- **Circles are NOT created by the script** — legacy `album.user` → Circle
  `author` and `album.assignTo` → Circle `assigned_staff` exist only as the
  optional section 6 of the notebook, for when circle work unblocks.
- **`postcards.website` was added** for the album split (schema migration
  `20260811060000_add_postcard_website`) — 661 of the 667 non-dedicated
  albums carry a `website` and `postcards` had nowhere to put it.
- **Stale non-dedicated `collections` are deleted** at the end of the run
  (see [Cleaning up an earlier run](#cleaning-up-an-earlier-run)).

## Field mapping — Directory

Legacy `api::directory.directory` → new `collection_types`. The v1 directory
list is **reconciled to the fixed v2 set** — fixed v2 names/slugs win:

| Legacy directory (slug) | New collection type | `has_dedicated_collection` | `priority` |
|---|---|---|---|
| Postcard StarPartner Stays (`mindful-luxury-hotels`) | Properties (`properties`) | true | 1 |
| Food and Beverages (`food-and-beverages`) | Restaurants (`restaurants`) | false | 2 |
| Postcard Events (`postcard-events`) | Events (`events`) | false | 3 |
| Postcard Shopping (`postcard-shopping`) | Shopping (`shopping`) | false | 4 |
| Designer Tours (`mindful-luxury-tours`) | **skipped** — dx-card migration later | | |

| Legacy field | New column | Notes |
|---|---|---|
| `description` | `description` | trimmed; empty → NULL |
| `logo` (media) | `icon` | the logo **url string** (absolutized against `CMS_BASE_URL`) — `collection_types.icon` is a string column, not a media FK |
| `name`, `slug` | — | replaced by the fixed v2 names/slugs above |
| `label`, `seo`, timestamps | — | **dropped** |

Any directory that is neither mapped nor skipped is printed under
`MANUAL REVIEW (unmapped)` — expected empty.

### Legacy postcards hanging off a non-dedicated album

A legacy `postcard` whose `album` is now a postcard cannot get a
`collection_id`. `scripts/postcard.py` handles this: it reads the
album→postcard map, sets `collection_id = NULL`, and inherits
`collection_type_id` + geo from the album-derived postcard. **0 such
postcards in prod**, 6 in dev — the branch exists for completeness and
prints them for review.

## Output artifacts — two album id maps

Written to the repo root, suffixed per environment from the DB name in
`DATABASE_URL` (`development` → `_dev`, `production` → `_prod`):

| File | Contents | Consumed by |
|---|---|---|
| `legacy_album_id_map{_dev,_prod}.json` | legacy album id → **collection** id (dedicated types only) | `scripts/postcard.py`, `scripts/journey.py` |
| `legacy_album_postcard_id_map{_dev,_prod}.json` | legacy album id → **postcard** id (non-dedicated types) | `scripts/postcard.py` |

The collection map keeps its original meaning — an entry means "this album is
a collection". Restaurants/Events/Shopping albums are absent from it, which
is exactly why `journey.py` now skips the (rare) itinerary hanging off one.

## Cleaning up an earlier run

A DB migrated before the split holds `collections` rows for the
non-dedicated types (660 in prod: Restaurants 341, Shopping 235, Events 84).
After moving the albums, the script deletes them — but **aborts instead of
cascading** if anything still references them, printing ready-to-paste
remediation SQL per dependency (`postcards`, `subcollections`,
`facet_assignments`, `collection_cluster_entries`, `circles`).

On the current prod DB the only blocker is **588 geo-derived
`collection_cluster_entries`**; deleting them is safe because
`scripts/cityguide.py` re-derives the same content as
`entry_type = 'postcard'` rows on its next run. `scripts/truncate_all.py`
plus a full re-migration is the other route.

## Idempotency

`collection_types`, `collections` and album-derived `postcards` all upsert on
`slug` (`ON CONFLICT (slug) DO UPDATE`). Cover-image media rows are
found-or-created by url. Generated slug suffixes are stable because
processing is id-sorted, and an album re-uses the slug its postcard already
owns (looked up through the previous run's album→postcard map). Safe to
re-run.

## What needs manual work — checklist

1. **Unmapped directories** — `MANUAL REVIEW (unmapped)` should be empty; any
   entry means a new legacy directory appeared and needs a mapping decision.
2. **No-directory albums** (~35) — they default to Properties; review the
   printed list and reassign collection types where wrong.
3. **Geo misses** — regions not found (~15: Santa Cruz, Luang Prabang, Dubai,
   ...) and ambiguous localities (~12: Shanti Nagar ×2) leave the FK NULL;
   fix by hand after deciding the right target rows.
4. **Unmatched companies** (~6) — albums whose company relation/slug found no
   `companies` row keep `managed_by_company_id` NULL.
5. **Slug review** — generated/de-duplicated `-2` suffixes are
   customer-facing; review anything that looks off.
6. **Circles** — run notebook section 6 when circle work unblocks (needs
   `USER_MAP_FILE` in `.env` pointing at the right per-environment user map).
7. **Stale non-dedicated collections** — if the script aborts, run the
   printed remediation SQL (see
   [Cleaning up an earlier run](#cleaning-up-an-earlier-run)).
8. **Album fields with no postcards column** — the
   `MANUAL REVIEW album fields with no postcards column` list should be
   empty; an entry means a non-dedicated album started using `seo`,
   `media_kit`, `additionalInfo`, `sustainability` or `company`, which
   `postcards` cannot hold.
9. **Event details** — only `start_date` is migrated;
   `end_date`/`is_recurring`/`recurrence_rule`/`venue` need filling in the
   CMS if the business wants them.
10. **Deferred work** — Journey subcollections, facets
    (`album_themes`/`category`/`environment`/`cuisines`), postcards and
    memories all have their own tracker rows.

## Prerequisite — schema migration

`postcards.website` must exist. Apply
`schema/migrations/20260811060000_add_postcard_website` before running this
step (e.g. `npx prisma migrate deploy`); the script fails on the INSERT
otherwise.

## Run order

```text
seed → geo → media → company → users → scripts/directory_album.py
```

Must run **after** geo (country/region/locality lookups), media (cover
reuse), company (managed_by links) and seed (base collection types), and
**before** the postcards/memories migrations (they need both album map
files). Or just run `python scripts/migrate_data.py`, which sequences
everything and stops on the first failure.
